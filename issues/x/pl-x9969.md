title: Opt-in check that ids mentioned in bodies exist
type: feature
status: open
created: 2026-10-19
---

Issue bodies cross-reference each other by id ("blocked on pl-7k3qx"). When the named issue is later deleted or its id mistyped, the reference dangles silently. The referring file is still valid, so this is not a parse error: it is a policy some trackers want enforced and others don't.

Proposed: an opt-in reference check.

- Enabled per tracker, e.g. `"check_references": true` in punchlist.json, so a project that wants it gets it from plain `punch check` (and from anything calling the check API), without remembering a flag. A `--references` flag on `check` could run it ad hoc where the setting is off.
- Only ids with this tracker's own prefix are checked: `<prefix>-` plus `id_length` characters of the id alphabet, on word boundaries. A body mentioning another tracker's ids (a different prefix) is never flagged.
- Each dangling reference is reported as `path:line: reference to <id>, which does not exist`. A reference to a closed issue is fine; it exists.
- Header fields are already covered (`parent`); this is body text only.

Measured motivation: a ~280-issue tracker whose bodies hold ~25 cross-references after an import, verified once by a shell loop that would otherwise be repeated after every deletion.
