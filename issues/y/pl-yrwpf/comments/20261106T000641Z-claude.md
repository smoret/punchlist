Decided, for a team tracking a multi-step pipeline: a local, writable kanban board, not read-only first -- a board you can't drag is just `punch list`.
- Lanes are `statuses` in config order; order within a lane is `rank` (a drop sets the midpoint of its neighbors); `category` is the card's chip; `depends-on` shows as a blocked badge.
- `punch serve`: stdlib ThreadingHTTPServer on 127.0.0.1, one vanilla HTML/JS page shipped as package data, a JSON API whose writes go through the same validated operations as the CLI (moved from cli into a new ops module). Polls a fingerprint of the issue files so agents' edits show up; a move carries the expected old status and gets 409 if the file changed under it.
- No git from the UI, and git is not required: issues may live on plain disk. The comment author is resolved once at startup.
- Not shared beyond the machine: shared issues live in a repo others clone and serve themselves.
