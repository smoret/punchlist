Design agreed: optional punchlist.json key line_endings = platform (default) | lf | crlf, validated on load; every write goes through one helper; punch init --line-endings sets it for the new punchlist.json. Reads are unchanged (they already accept either ending). Not building the 'keep each file's existing endings' option: a new issue or comment has no existing file to copy from, so it would still need lf/crlf/platform as a fallback, and a fixed setting already matches a repo's .gitattributes. Can be added later if a real use needs it. Ships as 0.4.0.
