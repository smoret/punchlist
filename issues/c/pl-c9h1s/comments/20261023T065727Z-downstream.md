But one-file `show` is the right property to keep, and a symmetric link has no direction to treat as the single source of truth anyway.

3. **Yes, `set A related=B` should write B too**, and removing the link should remove both sides, the same for `new --related`. The alternative fails quietly: our agents run one command per intent, and a second "now go set the other side" step is exactly what gets dropped. Writing two files is fine for us: both land in the same commit as the rest of the work, and the diff shows both ends.

4. **Yes, `check` should report a one-sided link, on by default.** If `set` keeps pairs, a one-sided link only comes from a hand edit or a merge that took one file's side. `check` already reads everything, so it costs nothing, and we run it as a test, which is where we'd want to catch it.
